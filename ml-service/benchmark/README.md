# Forecasting Benchmark — real data, honest metrics

This proves the demand-forecasting models work on **real** retail data (not the
app's synthetic seed data), using a fair evaluation method.

## Why this exists
The in-app forecast demo runs on seeded stock-movement data, which is a smooth
synthetic curve — so any "accuracy" measured on it is meaningless. This benchmark
measures accuracy on a **real public dataset** so we can quote a defensible number.

## Dataset
**UCI Online Retail** — ~500k real transactions from a UK online store
(Dec 2010 – Dec 2011). We clean it (drop cancellations, returns, non-product
codes) and aggregate to **weekly demand per product** — the exact signal a demand
forecaster consumes.

## Method — rolling-origin (walk-forward) validation
The only fair way to evaluate a time-series model: never let it see the future.

```
train on weeks[0:t]  →  forecast weeks[t:t+H]  →  score vs actual  →  slide t forward  →  repeat
```

Every model is also compared against a **naive baseline** (recent-average
persistence). A forecast is only worth anything if it **beats naive** — this is the
single most important and most-often-skipped check in forecasting.

## Models
| Model | What it is |
|---|---|
| `naive` | mean of last 4 weeks (the bar to beat) |
| `moving_average` | mean of last 8 weeks |
| `ets` | Holt-Winters exponential smoothing (statsmodels) |
| `prophet` | Facebook Prophet (trend + yearly seasonality) |

> **Honest note on LSTM:** deep models like LSTM need hundreds+ of points per
> series to beat statistical methods. Real per-product retail history is short
> (~1 year weekly ≈ 50 points), so LSTM typically *loses* to ETS/Prophet here.
> Using the right tool for the data size is itself a real finding worth reporting.

## Metrics
- **MAPE** — mean absolute % error (lower = better)
- **sMAPE** — symmetric MAPE (robust when demand hits zero)
- **MAE** — mean absolute error (units)
- **skill vs naive** — `1 − model_MAE / naive_MAE`; **> 0 means it beats naive**

## Run it
```bash
cd ml-service
python benchmark/download_data.py      # one-time, ~23 MB
python benchmark/run_benchmark.py --products 50 --horizon 4
```
Outputs `results.json` + prints a summary table.
